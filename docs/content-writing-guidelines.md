# Content Writing Guidelines

This guide standardizes how static pages are written and structured.

## Canonical structure

Use the shared data model in lib/static-page-content.ts and render pages with components/sections/static-page-layout.tsx.

Each page should include:
- Eyebrow: one-word category such as Legal, Workflow, Collaboration.
- Title: clear noun phrase.
- Intro: one concise paragraph describing intent.
- Sections: 2-5 focused sections.
- Bullets: use only when detail can be scanned quickly.

## Writing style defaults

- Lead with practical outcomes, not abstract claims.
- Use short paragraphs (1-2 sentences each).
- Keep tone direct and professional.
- Avoid inflated wording and marketing-heavy language.
- Prefer specific nouns and verbs over adjectives.

## Section rules

- Section title should describe a single concern.
- Each section should answer one user question.
- If a list exceeds 5 bullets, split into two sections.
- End with action clarity (what user should do next).

## Content checklist

- Is the page useful without additional context?
- Is each paragraph under ~35 words?
- Are bullets parallel in grammar and tone?
- Does metadata match title and intro intent?
- Is terminology consistent with existing pages?
